# 输出模板

回答语言跟随用户。下面的模板是结构，不是逐字要求；简单问题可以压缩（例如只有一条论断时不必列表），但四类内容——能确认的、不能确认的、有争议的、来源表——只要相关就不能省。

## 研究模式：回答

```markdown
**结论**（1–3 句，直接回答问题；有把握就说有把握，没有就说没有）

检索范围：截至 YYYY-MM-DD；时间范围 <用户指定或本次采用的范围>；共打开 N 个来源，其中 M 个读到正文/截图。

## 能确认的
- 论断一 [S01][S03] （可信度：高 — 一手直述，2 组独立来源；as of 2026-09-10）
- 论断二 [S02] （可信度：中 — 单一官方来源，未见反证）

## 还不能确认的
- 说法 X：只有 S05（二手转述）提到，未找到原始出处；缺少：<需要什么证据>
- 说法 Y：S06 被反爬拦截，截图也未能渲染，本次未读到正文

## 存在争议的
- 关于 Z：S01（官方）称 A；S04（独立测试）称 B。两者测试条件不同（……）。本技能不替任何一方补充解释。

## 我的判断（推测）
根据现有证据……（明确写出这是综合判断，说明依据哪几条论断，以及什么新证据会改变它）

## 时效复查
- 检索了"<关键词> 更新/更正/最新"：<有/无>新信息。<若有：哪条论断因此改变>

## 来源
（粘贴 `ledger.py render --cited-only` 的输出；每条含发布时间、访问时间、链接状态、读取方式）

证据目录：web-evidence/（ledger.json、pages/、shots/）
```

要求：
- 每个关键事实后紧跟来源编号；一段全部来自同一来源时段末标一次即可，不要给每句话复制同一组编号。
- 只引用 `read` 为 text/screenshot/both 的来源。只有摘要的不进来源表，最多在"不能确认"里提及"搜索结果提示……但未能读取"。
- 推测处写"这是推测"；资料不足写"资料不足"，不要用流畅的句子掩盖空缺。
- 编号来自 `ledger.py render`，不要手工重排。

## 审计模式：审计报告

```markdown
# 引用审计：<文件名或内容描述>

审计时间：YYYY-MM-DD HH:MM UTC。共提取 N 个链接、M 条附链接的关键论断、K 条无来源的关键论断。

## 1. 链接健康
| 链接 | 状态 | 说明 |
|---|---|---|
| https://… | OK | 已读正文 |
| https://… | GONE (404) | Wayback 有 2024-03 快照：<url> |
| https://… | BLOCKED (403) | 脚本被拒；截图确认页面存在，内容见 shots/S04.png |
| https://… | SUSPECT_SOFT404 | 200 但跳转到首页，原文已不在 |

汇总：OK x，GONE y，BLOCKED z（其中 w 个已用截图确认），…

## 2. 逐条论断
| # | 原文中的论断 | 所附来源 | 判定 | 依据 |
|---|---|---|---|---|
| C01 | "……" | S01 | 支持 | 页面原句："……" |
| C02 | "……" | S02 | 部分支持 | 页面说的是"计划推出"，原文写成"已推出" |
| C03 | "……" | S03 | 不支持（页面未提及） | 通读正文与 --find 均未找到相关内容 |
| C04 | "……" | S04 | 不支持（页面说法相反） | 页面原句："……" |
| C05 | "……" | S05 | 无法核验 | 链接 GONE，无快照 |
| C06 | "……" | — | 无来源 | 关键数字，建议补来源或删除 |

判定标准：支持＝原文直述；部分支持＝方向一致但程度/时间/条件不同；不支持＝页面没提或说法相反；无法核验＝读不到页面。

## 3. 修正建议
- C02：改写为"……（S02 称计划于 Q4 推出）"。
- C03：删除该引用，或替换为 <找到的正确来源 S07>。
- C05：可改引 Wayback 快照并注明；或寻找现行页面 <S08>。
- 无来源论断：……

## 4. 总体评价
<一两段：这份回答的引用质量如何，主要问题类型（编造 URL / 过度解读 / 过期）、哪些结论受影响>

证据目录：web-evidence/
```
