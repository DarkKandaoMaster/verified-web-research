# 可信度评定与来源分类

可信度不是对"这件事是不是真的"的裁决，而是"现有证据能把这条论断支撑到什么程度"。它由下面四个维度决定，写在 `add-claim --basis` 里，让读者能复查。

## 四个维度

| 维度 | 取值 | 说明 |
|---|---|---|
| **直接性** | 一手 / 二手 / 三手 | 一手：官方公告、当事人原话、原始论文/数据/代码、法院文件、财报。二手：媒体报道、分析文章。三手：综述的综述、百科、社交媒体转述。 |
| **独立组数** | 1 / 2 / ≥3 | 按"证据路径"分组：同一通稿的所有转载 = 1 组；引用同一匿名信源的多家媒体 = 1 组；同一数据集的多篇分析 = 1 组。官方公告 + 独立记者实测 + 第三方数据 = 3 组。 |
| **正文支持程度** | 直述 / 需推断 / 仅相关 | 直述：页面原句就是这个意思（`--quote` 能对上）。需推断：要结合几句或做简单计算。仅相关：页面谈的是相近话题，没说这句话——**这不算支持**。 |
| **时效** | 当前 / 可能过期 / 已过期 | 论断本身有生命周期：价格、版本号、政策、职位、"最新"都会过期。写清 `as_of`。 |

## 评级规则

- **高**：一手来源直述，且 ≥2 个独立组（或唯一权威一手来源 + 专门找过反证但未找到，并注明检索范围）；时效在有效期内。
- **中**：满足下列任一：只有 1 个独立组；只有二手来源但 ≥2 组互相独立；一手来源但需推断；时效可能过期。
- **低**：只有三手来源；来源之间矛盾且无法裁决；只有搜索摘要/未读正文（这种情况优先不引用，而不是标低）；论断依赖推测。

`ledger.py validate` 会在 `confidence=high` 但独立组数 < 2 时给出警告，需要在 `--basis` 里解释为什么一个来源足够（例如"这是该公司自己的财报数字，问题问的就是公司披露了什么"）。

## Observed / Reported / Assessed / Forecast / Unknown

写回答时给每条关键论断的性质定位，避免把"有人这么说"写成"事实如此"：

- **Observed（可查验的事实）**：文件、数据、代码、实测，任何人打开链接都能看到同样的东西。
- **Reported（有人报道/声称）**：媒体报道、官方声明、当事人说法。官方说"提升 2 倍"是 Reported，除非有独立复现。
- **Assessed（我们的综合判断）**：把多条证据综合后得出的推断。回答里必须写"这是推测/判断"。
- **Forecast（预期）**：对未来的判断，给区间而不是点值。
- **Unknown（不知道）**：找不到证据或证据矛盾。直说，不补全。

## 什么不算独立来源

- 转载、编译、摘编自同一篇原文的所有页面。
- 引用同一份新闻稿/同一个匿名信源的报道。
- 同一作者/机构在不同平台发的同一内容。
- AI 生成的聚合页、内容农场。
- 维基百科条目及其引用的来源：维基本身是三手，去引用它引用的那个来源。

## "没找到反证"的写法

不写"没有争议""业界公认"。写：
> 在本次检索范围内（关键词：X、Y、"X 争议"、"X 质疑"；来源：S01–S07）未见与此不同的说法。

如果论断是热点或有利益相关方，还要说明有没有专门看过对立阵营的渠道。

## 时间标注

- 每个来源：`published`（页面自己声明的发布/更新时间，脚本从 meta 抽取，抽不到就写"未知"）和 `accessed`（我们访问的时间）。
- 每条论断：`as_of`——这条信息"截至何时"成立。
- 回答开头写检索截止时间（`cutoff`）。时效复查发现新信息改变了判断时，在回答里标"更新：……"，不要悄悄改写。
